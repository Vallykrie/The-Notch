Approval & question cards · layout proposals v1

Each panel is drawn at the real 640×190pt notch size, with the real font and colours, zoomed 1.45× so it reads on this page. The cards stay notices: you answer in the agent, as today, because approving from the notch didn't land reliably in Claude Code. So each layout's job is to make three things obvious at a glance: what is being asked, what the choices are, and how to get to where you answer. Switch layouts above, and each layout is shown against the same five cases.

layout

WHAT'S WRONG WITH CURRENT

  • The tab bar eats the top 30pt of a card that has no use for tabs while something is blocked.
  • The mascot is a 22–30pt icon wedged beside a two-line headline, so the headline wraps early.
  • Option descriptions get cut off with "…" on the same line as their labels.
  • The way to answer ("Open Agent to answer · click elsewhere to dismiss") is dim footer text, so the one action is the least visible thing on the card.

A · FOCUS

  • No tab bar while a prompt is up; the card is the whole panel.
  • A left column for who (a big mascot, agent, project, how long it has been blocked), a right column for what.
  • The command sits in a code block; options form a 2×2 grid with descriptions on their own line.
  • A real "Answer in Claude Code ↗" button, plus a dismiss ✕.

B · TERMINAL MIRROR

  • Draws the prompt the way the CLI shows it: ● Bash(…), then the numbered choices with ❯ on the first.
  • Shows exactly what you'll see in the terminal, and which number to press.
  • A slim header carries the agent, the project and the timer; the open button sits in it.
  • The most "dev tool" feel, and it matches the retro mono look.

C · BANNER

  • A coloured banner strip on top (amber for a permission, yellow for a question) with the mascot, who, how long, and the actions on the right.
  • Below it, the full width goes to the content: the command large and readable, or the options as full-width rows.
  • The most familiar "notification" shape, and the fastest to scan.
